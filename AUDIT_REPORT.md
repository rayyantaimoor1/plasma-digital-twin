## Category 1 — Consistency with the seven non-negotiable principles

Each principle re-checked against the **current** code, not its state when first built.

### Principle 1 — Physics engine is a real 0D global model; every output derived from Te/n_e
**PASS.** `digital_twin/physics_engine.py`: `solve_electron_temperature` (line 336) solves the
particle balance via `scipy.optimize.brentq` (line 371); `solve_plasma_density` (line 402) solves
the power balance. All derived indices flow from Te/n_e in `_derived_indices` (line 507) and
`sheath_and_ion_energy` (line 438). No hand-fit output curves.

### Principle 2 — Hidden confounders never reach the classifier as features
**PASS — airtight.** The single enforcement point is `features_and_labels`
(`digital_twin/dataset_generation.py:325-327`), which returns `frame[FEATURE_COLUMNS]` only.
A repository-wide grep for `wall_temp_drift`, `electrode_age`, `gas_purity`,
`true_process_quality`, `nominal_process_quality`, `CONFOUNDER_COLUMNS` across `ai_module/` and
`dashboard/` returns **zero matches** — no confounder or quality column is referenced anywhere in
the AI or dashboard code. Sub-Module 2.8's defect regressor uses
`X = train_df[FEATURE_COLUMNS]` with `y = train_df["true_defect_probability"]`
(`ai_module/uncertainty_quantification.py:126-127`): the confounded defect probability is the
regression **target**, never a feature.

### Principle 3 — Classification success = significant improvement over the LogReg baseline
**PASS.** See Category 6 (verified implemented **and** invoked).

### Principle 4 — Anomalies are physics-relationship violations, not out-of-range values
**PASS, and still correct after the sheath fix.** `ai_module/anomaly_detection.py` detects on the
physics residual (`relative_residuals`, line ~230) computed via `simulate()` at score time, so it
tracks the current physics automatically. `RESIDUAL_COLUMNS` excludes the two input setpoints.
Note `etch_rate_nm_min` is a feature and *does* depend on ion energy (which the sheath fix changed);
because both the normal manifold and the scored points are generated by the **same current**
`simulate()`, they stay self-consistent — the 358-test run includes 2.2's ~93%-recall / ~0%
range-check assertions, which pass under current physics. (See Category 2 for the timing detail.)

### Principle 5 — Recommendations are counterfactual (real re-simulation, no static text)
**PASS.** `ai_module/recommendation_engine.py` calls `simulate()` at three points:
`_evaluate_candidate` line 196 (re-simulate each candidate), `recommend` line 260 (baseline), and
`verify_recommendation` line 393 (verify an applied change). `prediction_text` is built from those
real results (line 219-227). There is **no** placeholder/static branch — grep confirms every
recommendation path runs the twin. Test `test_every_recommendation_is_grounded_in_real_resimulation`
re-runs `simulate()` on each recommended config and asserts the reported after-values reproduce
exactly.

### Principle 6 — Physics validation is semi-quantitative with a stated tolerance band
**PASS.** `digital_twin/physics_validation.py`: `run_literature_benchmarks` (line 178) compares
computed vs reference values with per-check `tolerance_pct` and a `passed` property; 5/7 checks pass
and the 2 failures are reported honestly. (But see Category 3 re: FE-1.6.1 plot wording.)

### Principle 7 — Tree ensembles only for the core classifier; no deep learning in 2.1
**PASS.** `ai_module/classification.py` uses only RandomForest / XGBoost / LogisticRegression.
PyTorch appears **only** in `ai_module/autoencoder_detector.py` (the optional 2.2.6 stretch feature)
and is kept out of the base `requirements.txt` (it lives in `requirements-optional.txt`). The core
task never imports torch.

**Category 1 result: all seven principles satisfied by the current code.**

## Category 2 — Regressions from the sheath-voltage fix

**Key finding — the premise needs correcting.** The audit request assumed the sheath fix
(`c9f1db6`, now `17cf456` after the Co-Authored-By history rewrite) "landed after 1.1, 1.4, and 1.5
were already built." The actual chronological commit order (`git log --reverse`) is:

```
b384afa  Sub-Module 1.2 (original, power-independent sheath bug)
17cf456  Fix Sub-Module 1.2: sheath voltage now depends on RF power   <-- the "c9f1db6" fix
f4a53d9  Sub-Module 1.1
ce59712  Sub-Module 1.4
bc1b2dc  Sub-Module 1.5
ace1d28  Sub-Module 1.2: Child-Langmuir / RF-voltage sheath (Option C)
```

So **1.1, 1.4, and 1.5 were built AFTER the sheath fix** — they never depended on the buggy
power-independent sheath. The change that landed *after* them is **Option C** (`ace1d28`), which
introduced `rf_voltage_v` and the Child-Langmuir sheath. Option C was verified at build time to
leave the default (no-`rf_voltage_v`) path **byte-identical**, so downstream calibrations built on
the default physics remained valid. Empirical re-verification now:

- **1.1 calibration still valid:** `chamber_config.DEFECT_WARNING_THRESHOLD = 0.55`, and the Stress
  Test preset still crosses it under current physics — measured **defect = 0.561** (fires), vs
  Stable/Exploratory **0.464** (don't). Test `test_stress_test_configuration_triggers_defect_warning`
  passes.
- **No stale hardcoded physics values downstream:** grep for `ion_energy` / `sheath_voltage` /
  literal `200` across `ai_module/` + the 1.x modules shows only (a) dynamic reads of
  `result.ion_energy_ev` from `simulate()`, and (b) `CORRELATION_COLUMNS` list entries — no
  hardcoded magic numbers calibrated against the old sheath voltage.
- **1.5 sensitivity:** `ion_energy_ev` sensitivity to power is now non-zero
  (`test_ion_energy_has_nonzero_sensitivity_to_power`) — the opposite of the old bug — confirming
  1.5 reflects the fixed physics.

**Category 2 result: no regressions. The one post-1.1/1.4/1.5 change (Option C) preserved the
default path, and all downstream calibrations verify correct under current physics.**
